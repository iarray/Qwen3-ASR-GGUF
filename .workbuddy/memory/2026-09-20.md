## 后续修复：开始按钮不可见 + 英文单词空格丢失

### 1. 「开始识别」按钮被挤出窗口（用户反馈：是不是少了开始按钮）
- 根因：`pack` 按调用顺序分配空间，"输出区"排在"底部按钮条"之前且带 `expand=True`，
  窗口设 820px 而内容需要 1137px，导致按钮条被压成 0 高度（`winfo_ismapped()==0`）。
- 修法：`bottom.pack(side=BOTTOM, fill=X)` 提前占位，`out.pack(...)` 移到 `_build_ui` 末尾；
  并把「开始识别 / 停止」挪到文件工具条上（紧邻"添加文件"，永远可见）。
- 顺带把 `tk.Text` 的 `height` 显式设为 10（默认 24 会撑高请求尺寸），
  初始几何尺寸改为按屏幕自适应 `min(1240, sw-80) x min(880, sh-110)` 并居中。

### 2. 英文词间空格全部丢失
- 根因：`subtitle.py::split_into_clauses` 里 `if not text.strip(): continue` 把对齐器输出的
  纯空白项（`' '` / `'. '`，本样本共 53 个）全部丢弃，导致 `Oh, hello. I didn't know you were there.`
  变成 `Oh,hello.Ididn'tknowyouwerethere.`。
- 修法：① 只判 `if not text:` 保留空白项；② 新增 `_smart_join()`，按"两侧是否都是 ASCII 词字符"
  决定补不补空格；`pack_subtitles` 整行拼接与 `merge_short_segments` 短行合并都改用它。
  CJK 不受影响（`3` + `个` → `3个`）。
- `test_subtitle_speaker.py` 增补第 [8] 组回归用例，现共 22 项断言全通过。

## 说话人识别改为 onnxruntime（DirectML / CUDA / CPU）

用户要求：`pyannote.audio 原生 API 完全基于 PyTorch，改为使用 onnxruntime-gpu 或 onnxruntime-directml`。

### 关键判断
pyannote 3.1 的说话人分离配方里**只有两个神经网络**，其余都是 numpy/scipy 算法，
所以可以完整搬到 onnxruntime：
- 分割：`pyannote/segmentation-3.0`（PyanNet + SincNet），10s 窗 → 589 帧 × 7 powerset 类
- 嵌入：`pyannote/wespeaker-voxceleb-resnet34-LM`，5s 窗 → 256 维（**未归一化**）
- 聚类：`AgglomerativeClustering(method=centroid, metric=cosine, threshold=0.7045654963945799, min_cluster_size=12)`

### 踩坑记录（ONNX 导出）
- **`torch.onnx.export` 必须显式 `dynamo=False`**。新版 dynamo 导出器会忽略 `dynamic_axes`
  把 batch 固定为 1，且慢约 150 倍（92.6s → 0.6s），精度也更差（7.96e-05 → 2.57e-05）。
- `asteroid_filterbanks` 的 `ParamSincFB.filters()` 里 `torch.clamp(tensor, scalar, scalar)`
  无法被 ONNX 导出器解析，要 monkey-patch 成 `torch.maximum/minimum`。
- 嵌入模型整模型导出会在 fbank 的 STFT 处炸（`size of tensor a (400) must match b (401)`），
  改为**只导出 `model.resnet`**，fbank 用 numpy 复刻。
- numpy fbank **必须先 `×32768`**（`x = waveform * (1 << 15)`）：它决定 `log(max(mel, eps))`
  的截断位置，漏掉会让静音帧偏差到 10.17（相对 0.79）。补上后真实语音 max|Δ|=5.5e-4（相对 3e-5）。

### 验证
- 导出逐位对齐 PyTorch：分割 max|Δ|=8.2e-05、argmax 一致率 100%；嵌入 max|Δ|=3.5e-07、余弦相似 1.000000。
- **端到端 30s 双人英文**（纯 onnx 门面调用 vs pyannote 原生 CPU）：
  语音帧 IoU = 1.0000，帧级说话人标签一致率 = 1.0000，段数与边界完全一致。
- **DirectML**：30s 音频走 `DmlExecutionProvider`，2 人 / 12 段，与 CPU 一致；

- GUI 冒烟：后端下拉框、提示标签均可见；1000×640 最小尺寸下开始/停止/进度条/提示都在窗口内。

## 顺带修掉一个隐蔽的既有 bug：DML 下字幕时间戳全为 0

- 现象：端到端跑 30s 样本，SRT 所有行都成了 `00:00:00,000 --> 00:00:00,050`，且没有 `[spk0]` 前缀
  （因为时间戳全 0，按时间绑定说话人自然绑不上）。
- 定位：在对齐器之外加探针，发现 `np.argmax(logits[:4000])` 恒为 0，
  进一步查出 **logits 全是 NaN**，再往上查到**编码器输出全是 NaN**。
- 根因：`QwenAudioEncoder._run_backend()` 在 DirectML 下把 hidden_states **零填充**到固定长度
  `dml_pad_to` 秒。DirectML 后端收到全零 hidden_states 时内部归一化算子会算出 NaN，
  **NaN 会污染整段输出**（与 attention mask 无关 —— mask 全 0 也照样 NaN）。
  - ASR 主流程每片音频都补齐到整 40 秒，`seq_len == h_target_len`，走不到补齐分支，所以看不出来；
  - 对齐器传的是真实语音切片（通常 < 40 秒），必然走补齐分支 → 时间戳全 0。
- 修法：补齐时**复制末帧**而不是补零。实测与 CPU 结果 max|Δ|=1.4e-4（回归测试里为 5.1e-5），
  补齐区本来就被 mask 掉且最终会被截断，所以语义上无损。
- 修复后 SRT 正常：`00:00:06,720 --> 00:00:08,480 / [spk1] Hello. Hello.`，13 条字幕。
- 已加 `test_dml_encoder_padding.py` 守住（CPU 基线 / DML 短音频无 NaN / 形状一致 / 数值接近 /
  整 40s 无 NaN / 0.1s 极短音频无 NaN）。
